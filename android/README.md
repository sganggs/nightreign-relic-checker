# 夜幕验物 Android

> **版本说明（v0.3.0）**：手机版同步到 **v0.3.0**（`versionName` 0.3.0 / `versionCode` 2），Release 附件为
> `NightreignRelicChecker-Android-v0.3.0.apk`。桌面端 v0.3.0 的「词条反查」「首领数据」「角色属性」「增伤排名」四页
> 与「存档检查」都已移植到手机上，数据与判定口径和桌面端同源。底栏为 **检查 / 反查 / 词条库 / 数据 / 设置**，
> 「数据」是枢纽页，从这里进入首领数据、角色属性、增伤排名、存档检查四个子页。手机版的取舍与尚未移植的部分见
> [与桌面版的差异](#与桌面版的差异)。

夜幕验物 Android 是一个完全离线、手机优先的遗物检查与游戏数据查阅工具。包名为
`com.nightreign.relicchecker`，使用 Kotlin、Jetpack Compose、Material 3 与 Preferences DataStore。
界面沿用桌面版的深黑紫色视觉语言，并针对手机的触控、底部导航和底部抽屉重新布局。

## 导航

| 底栏 | 内容 |
| --- | --- |
| 检查 | 三词条手动检查 |
| 反查 | 词条反查（一级页，紧跟「检查」） |
| 词条库 | 词条库浏览 |
| 数据 | 枢纽页 → 首领数据 / 角色属性 / 增伤排名 / 存档检查 |
| 设置 | 设置、数据版本、来源与关于 |

子页左上角是返回按钮，系统返回键与再点一次底栏「数据」都回到枢纽页。各页用 `rememberSaveable` 保存的状态
（搜索词、所选角色、增伤配置等）在切换底栏、返回枢纽后再进入时都会保留。

## 已实现

### 检查 / 词条库 / 设置

- 三词条手动检查，支持“普通 1.03”“普通旧池”“深夜正面”“顺序/互斥”四种口径：`effectId` 去重、非 `-1` 的
  `compatibilityId` 互斥、槽池一一分配，以及 `(sortId, effectId)` 规范排序。
- 深夜正面使用 AAA、AAB、ABB、BBB、AAC、ACC、CCC 七种真实三槽模板；界面始终说明这只是正面预检，
  界面只说明完整判定仍需具体遗物 ID 与逐行诅咒配对；要判完整的深夜遗物，可到「数据 → 存档检查」按行配对（这是本文的建议，界面里不写）。
- 三个全宽词条槽、支持名称/别名/分类/effectId 的归一化搜索、合法随机组合、规范排序与清空；
  词条库浏览、搜索、模式过滤、高密度列表与底部抽屉详情。
- 设置页可持久化默认模式、自动检查、选择器默认过滤和词条库紧凑显示，并离线展示隐私说明、GPL、
  数据版本、来源和真实记录数。Manifest 未声明 `android.permission.INTERNET`。

### 词条反查（底栏「反查」）

- 「按词条查」给出一条词条能出在哪些遗物、普通 1.03 / 普通旧池 / 深夜正面三种口径下所在的槽位池
  （按「N 孔层」标注）、深夜 A / B / C 池与诅咒池归属，以及同 `compatibilityId` 的互斥组；
  「按遗物查」给出一件遗物的槽位池构成与官方固定词条。
- 桌面端的「左列表 / 右详情」改为「列表 → 全屏详情」：详情里点互斥词条、池成员或出处遗物可跨方向继续往下跳，
  返回时逐层退回，并保留每一层的滚动位置。
- 横屏等矮屏时页签与搜索并成一行，列表下滑收起、上滑即回；遗物物品表载入失败时退化为只有词条库的索引，
  仍可看词条说明与互斥组（与 macOS 同口径）。

### 首领数据（数据 → 首领数据）

- 18 个夜王条目与 116 组首领的血量、削韧、八种承伤倍率、异常抗性与官方弱点，收录统计与桌面端一致；按出场场合分为
  夜王 / 守夜首领 / 据点首领 / 场景头目 / 封印监牢 / 其它场合，「随从/召唤物」「未放置」两个分组与非首领实体由
  「显示隐藏实体」开关控制。
- 顶部工具条选人数（单人 / 双人 / 三人）、模式（常规 / 深夜·深度 1–5）与变异个体，各层倍率连乘；
  代表行规则、换算与文案逐条移植自 macOS `RelicCore/BossData.swift`。
- 手机取舍：变异个体是工具条里的全局选择（不计 / 各行自带档位 / 指定档位），不是桌面端的逐行下拉；
  出处的地图名与 MSB part 在「展开全部出处」后显示（手机没有悬停）；搜索时各分组计数随结果更新。
  横屏 / 分屏时只把搜索框与设置行吸顶。

### 角色属性（数据 → 角色属性）

- 10 个渡夜者 1–15 级的八项属性与血量 / 专注值 / 精力 / 负重上限；「单角色」视图可在「本级卡片」与「全部等级」间切换，
  「同级对比」横向比十个角色的同一级，并可按列排序。
- 转职遗物可多选叠加，每一级标出「词条锚点 / 词条推算 / 词条沿用」；利普拉的交易在底部抽屉里选；
  负重上限与桌面端一样标注为遗留列。
- 宽表首列固定、其余列横向滑动，表头与各行同步横滚；横屏 / 分屏时工具条并成一行。

### 增伤排名（数据 → 增伤排名）

- 一列可折叠卡片：输出手段（战技 / 法术、武器、命中分段、伤害构成、攻击情境）→ 出击模式（常规 / 深夜与各槽位上限）
  → 局内武器词条 → 遗物 → 护符 → 其它增益 → 汇总（按推荐填满、清空、显示不生效项，另有固定在底部的总倍率条）→ 说明。
- 战技的武器列表含固定带这个战技的武器与局内战技池能抽到它的武器（战技数据 schemaVersion 3），武器抽屉里每把武器标
  「固定战技」或「局内可抽到」；动作套按所选那一把武器实解，命中段只取按 TAE 动画事件核实过的段。法术只列可施放的
  （施法器的法术池里抽得到的，不含本体残留的「风暴管束者」法术行）。
- 「其它增益 · 道具」里，学者的能力「携物知识」才有的 2／3 级道具效果在名字旁标「携物知识 N 级」（长按看说明），
  分栏说明写明等级来源；增益名字按实际提高的攻击类型写（如勇者肉块 3 级「提升物理与属性攻击力」，对法术也增伤）。
- 自组遗物复用 `:rules` 的 `LegalityChecker`：普通遗物用「普通 1.03」口径，深夜遗物用「深夜正面」口径加诅咒逐行配对，
  选了需诅咒的词条会自动配诅咒；不合法的遗物整件不计入。
- 配置引擎与桌面端逐行对拍（见[构建与测试](#构建与测试)）；「按推荐填满」与候选打分都在后台线程计算。
- **未移植**：桌面端页面底部的「全部增益一览」（每条增益单独按条件全部成立计算的查阅表）。

### 存档检查（数据 → 存档检查）

- 手机上没有游戏：先把电脑上的 `NR0000.sl2` / 无缝联机 `.co2` 拷到手机，再点「选择存档文件」，经系统文件选择器
  （Storage Access Framework）只读打开你在系统文件选择器里选中的文件（存档对比时再选一份）；不申请存储权限、不写回存档，单个文件上限 96 MB。
- 在本机解密并解析全部角色槽，逐件校验的项目与桌面端相同（遗物 ID 区段、`effectId` 与互斥查重、保存顺序、
  深夜遗物正负词条按行配对、唯一遗物的固定词条与重复持有）；可按「全部 / 仅非法 / 深夜遗物」过滤与搜索，
  带说明的词条可就地展开。
- 存档对比：再选一份存档，按角色槽列出「新增 / 减少」的遗物（与两个桌面端的实现一致，被改动的遗物显示为一减一增）。
- 导出报告：文本报告（.txt）或 CSV；「保存到文件」走系统的「创建文档」界面选择位置，「分享」经 FileProvider 交给其它应用。
  文件名形如 `夜幕验物-存档报告-NR0000-20260922-120000.txt`。
- **手机上没有**桌面端的「自动查找存档」与「拖拽打开」。读入的存档只保存在进程内存里，应用在后台被系统回收后需要重新选择。

## 工程结构

工程采用四个模块，避免 Android UI 与规则、数据解析相互耦合：

- `:rules`：纯 Kotlin。包含领域模型、四种模式、合法性检查、搜索归一化和随机组合。
- `:catalog`：纯 Kotlin + kotlinx.serialization。负责校验并解析权威词条 JSON，依赖 `:rules`。
- `:gamedata`：纯 Kotlin + kotlinx.serialization，依赖 `:rules` 与 `:catalog`，可在 JVM 上单测。根包是各页共用的
  `GameDataFiles`（数据集文件名、版本键与期望的 schema 版本，与 `data/` 下文件名逐字一致）、`GameDataJson`
  （共用的宽容 JSON 配置、带文件名的解码错误与版本校验）和 `GameDataHeader`（顶层元数据）；各页的 DTO、解析与纯逻辑
  分在 `lookup` / `bosses` / `heroes` / `ranker` / `save` 五个包里，逐条移植自桌面端（存档解析器移植自 Windows
  `savefile.go`，两端已互相对拍；其余以 macOS `RelicCore` 为准）。
- `:app`：Android/Compose UI 与 DataStore 设置，依赖前三个模块；各页界面在 `ui/{lookup,bosses,heroes,ranker,save}/`。
  `ui/gamedata/GameDataRepository` 懒加载数据集：首次进入某页时才在 `Dispatchers.IO` 上读入并解析对应 JSON，
  按「数据集 + 解析器 ID」做进程级缓存，旋转屏幕、切底栏、离开再进入都不重读，页面在解析途中离开结果照样进缓存；
  只缓存解析结果，不缓存原始 JSON 文本。数据页的导航、加载骨架与移植约定见 [`PAGES.md`](PAGES.md)。

根目录 `data/` 是唯一权威数据源。没有在 Android 工程中复制 JSON：

- `:app` 的 `main` assets source set 指向 `../../data`，六个数据集（词条库、遗物物品表与四套 v1.03.5 参数表数据集）
  全部打进 APK；
- `:catalog` 与 `:gamedata` 的 `test` resources source set 指向 `../../data`；存档检查的测试另外直接读仓库根
  `testdata/audit_cases.json`（桌面双端共用的对拍用例）。

因此更新根数据后，重新构建 APK 和运行测试即可使用同一份数据；Android 不需要运行 `scripts/sync-data.sh`。

## 发布构建与签名

`./gradlew assembleRelease` 产出未签名 APK；正式发布使用 `zipalign` 对齐后以
`apksigner` 签名（签名密钥不入库）。同一签名密钥必须长期保留，否则已安装用户
无法覆盖升级。第三方组件许可见 `THIRD_PARTY_NOTICES.md`。

## 构建与测试

在本目录运行：

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

根 `testDebugUnitTest` 任务会同时执行 `:rules:test`、`:catalog:test`、`:gamedata:test` 与
`:app:testDebugUnitTest`，当前共 **470** 个 JVM 测试：`:rules` 13、`:catalog` 8、`:gamedata` 426、`:app` 23。覆盖：

- 合法、重复 effectId、互斥冲突与 `-1` 豁免；池外词条、槽池模板不匹配和一一分配；七个深夜模板、非法 ABC 模板与深夜警告；
  `(sortId, effectId)` 排序、随机组合，以及搜索的大小写、重音、全半角、标点、别名、分类与 ID 归一化；
- 直接读取根数据得到的固定事实：527 条总记录、340 条当前普通池、290 条旧普通池，各数据集的版本校验、
  条目数与收录统计（与根 README 一致）；
- `:gamedata` 各页与桌面端同一批对拍用例：词条反查与 macOS / Windows 同一张对照表（lookup 包 43 个）；首领数据的固定事实、
  分组与换算（bosses 包 94 个）；角色属性的三端对照基线与逐格扫描（heroes 包 64 个）；增伤排名逐行比对桌面端导出的
  `CASE` / `CONFIG` / `OUTPUTS` / `TEXT` 对拍行（ranker 包 158 个，数据见 `gamedata/src/test/resources/ranker-crosscheck-dump.txt`）；
  存档检查用合成的 BND4 / AES-CBC 夹具测解析，并按 `testdata/audit_cases.json` 逐条对拍审计结论，另测报告与对比（save 包 59 个）；
- `:app` 的导航约定、首领页工具条布局与文案、角色页配色和增伤排名页面状态。

Debug APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`（约 15 MB）；未签名的 Release APK 约 10 MB。
UI 没有仪器测试，各页主要流程在模拟器上人工走查过。

## 与桌面版的差异

- **口径同源**：内置数据就是仓库根 `data/` 下的同一批文件；判定规则与数值换算在 `:gamedata` 里逐条移植自桌面端，
  JVM 测试钉住与 macOS `RelicCore` / Windows 测试同一批对拍用例，手机端的逻辑一旦与桌面端不一致，测试就会变红。数值口径与
  「未实测 / 推算 / 参数推断」之类的标注与桌面端一致，已知局限见 `macos/DataSources/PROVENANCE.md`。
- **首次进入要解析数据**：首领数据与增伤排名首次进入时要在后台解析 1.5–3 MB 的 JSON（buffs 2.96 MB、bosses 1.59 MB、
  skills 1.56 MB），中低端机上可能要等几秒，期间页面显示加载态；之后同一进程内不再重读，应用被系统回收后重新进入会再解析一次。
  各数据集的实际耗时可用 `adb logcat -s GameData` 查看。
- **存档检查**：只能通过系统文件选择器只读打开一个文件，没有自动查找与拖拽；报告导出用「创建文档」或分享；
  读入的存档只在进程内存里，应用被回收后要重新选择。
- **增伤排名**：没有「全部增益一览」。
- **首领数据**：变异个体是全局选择而不是逐行下拉；出处的地图名 / MSB part 要展开才显示。
- **设置**：没有桌面端「数据设置」页的导入 / 导出 / 恢复自定义词条库，始终使用内置词条库。
- **已知的界面局限**：应用没有处理软键盘内边距，弹出键盘时会盖住列表下半部分，横屏更明显，个别页面连搜索框也会被盖住（收起键盘即可看到结果）；
  少数页内分段控件的高度低于 48dp。
